# ReplayClipTrainer 修正内容

このファイルは、本プラグイン（ReplayClipTrainer）が元にしている [JumpInReplay](https://github.com/Atomus48/JumpInReplay) からの**修正点・機能追加を記録する開発ログ**です。ユーザー向けの機能説明は [README.md](../README.md) を参照してください。

対象ファイル: `ReplayClipTrainer/ReplayClipTrainer.h`, `ReplayClipTrainer.cpp`, `ReplayClipTrainerGUI.cpp`, `ClipFile.h`, `ClipFile.cpp`

## バグ修正

### 1. 変換中に日本語プレイヤーが混在しているとクラッシュ（PRI null未チェック）
- **症状**: `reclip_convert`で変換中にゲームがフリーズ→クラッシュ（`pluginsdk.dll`内でアクセス違反）。
- **原因**: `SaveCar()`内で`Car.GetPRI().GetBallTouches()`を呼ぶ際、`GetPRI()`がnullになりうるのにチェックしていなかった。
- **修正**: `Car.GetPRI().IsNull()`を確認し、nullなら0を使うように変更。
- 該当箇所: `ReplayClipTrainer.cpp` `SaveCar()`

### 2. クリップ変換した場面が正しく再現されない（ボールが中央のまま）
- **症状**: `reclip_convertClip`で変換した短い場面を再生すると、キックオフ演出が終わるまでの間にTickが進んでしまい、意図した場面がスキップされる。
- **原因**: `ControllGamePerTick()`が、プライベートマッチ自身のネイティブなキックオフカウントダウン中もTickを進め続けていた。
- **修正**: `gameWrapper->GetGameEventAsServer().GetReplicatedRoundCountDownNumber() == 0`（キックオフが終わっている）という条件を追加し、キックオフ中は一切処理しないようにした。
- 該当箇所: `ReplayClipTrainer.cpp` `ControllGamePerTick()`

### 3. 一度JumpInしてボールに触れると、次回以降ずっとボールが動かない
- **症状**: 一度JumpIn中にボールに触れる/スコアが変わると、以降のセッションでボールが二度と動かなくなる。
- **原因**: `setBally`フラグ（ボールを上書きするかどうか）が一度`false`になった後、`ControllGame()`のリセット処理に含まれておらず、次のセッションに持ち越されていた。
- **修正**: `ControllGame()`のリセット処理に`setBally = true;`を追加。
- 該当箇所: `ReplayClipTrainer.cpp` `ControllGame()`

### 4. 日本語プレイヤー名のHUD文字化け（部分対応）
- **症状**: HUDのプレイヤー名表示が日本語だと文字化けする。
- **原因**: `Car.GetOwnerName()`が内部でマルチバイト文字を欠落させる変換をしていた。
- **修正**: `Car.GetPRI().GetPlayerName().ToWideString()`＋`WideCharToMultiByte`によるUTF-8変換に置き換え。ヘルパー関数`WStringToUtf8()`を追加。
- **限界**: この修正だけでは直らず（□□の四角＝グリフ欠落）。`canvas.DrawString`自体が使っているフォントにCJK字形が無いことが原因と判明。ImGui経由でCJKフォントを読み込む対応を試みたが、BakkesMod共有のImGuiフォントアトラスをプラグイン側から後から拡張すると`bakkesmod.dll`がクラッシュすることが実機検証で判明したため**撤回・断念**。現状は文字化けしたHUD表示のまま。
- 該当箇所: `ReplayClipTrainer.cpp` `WStringToUtf8()`, `OneTimeSaves()`

### 5. クリップ変換中、リプレイ途中の無効な車（ゴーストカー等）でクラッシュ
- **症状**: `reclip_convertClip`実行時に`bakkesmod.dll`内でクラッシュ。
- **原因**: `OneTimeSaves()`が、リプレイ途中の任意のフレームで車情報（PRI・ローディング情報・チーム）を無条件に取得しており、その時点で車が無効（プレイヤー途中離脱等）だとクラッシュする。全編変換は常にフレーム0付近から始まるため今まで顕在化していなかった。
- **修正**: 各車の`CarWrapper`自体の`IsNull()`チェックを追加し、無効な場合は安全なデフォルト値を使うようにした。
- 該当箇所: `ReplayClipTrainer.cpp` `OneTimeSaves()`

### 6. 設定GUIのボタンを押すとクラッシュ
- **症状**: GUIの「Convert Clip Around Current Position」等のボタンを押すとクラッシュ（`bakkesmod.dll`内、同一オフセット）。
- **原因**: ImGuiの描画コールバック（ボタンクリック処理）の中から、`HookEvent`やファイル書き出しなど重いゲーム状態変更処理を同期的に呼び出しており、BakkesMod自身の描画処理と競合していた。
- **修正**: 該当処理を`gameWrapper->SetTimeout(..., 0.0f)`で次のティックまで遅延実行するように変更。
- 該当箇所: `ReplayClipTrainerGUI.cpp` `RenderSettingsGui()`内の各ボタン

### 7. クリップファイル保存時のクラッシュ
- **症状**: 「Save Clip to File」を押して変換が完了した瞬間にクラッシュ。
- **原因**: リプレイの物理ステップフック（`SaveGameState()`、1tickごとに呼ばれる）内で、変換完了と同時にファイル書き込み（`ofstream`書き込み・保存先フォルダの一覧再構築）を同期的に実行しており、上記6と同様にBakkesMod側の処理と競合していた。
- **修正**: ファイル書き込み処理を`gameWrapper->SetTimeout(..., 0.0f)`で遅延実行するように変更。
- 該当箇所: `ReplayClipTrainer.cpp` `SaveGameState()`

### 8. 保存したクリップを読み込んでも再現されない（ボール中央のまま・再生バー非表示）
- **症状**: 保存したクリップを「Load & Train」で読み込むと、ボールが中央のまま開始され、再生バー（タイムラインHUD）も表示されない。
- **原因**: 通常の「Convert」「Open Saved Replay」では`reclip_convert`/`reclip_openReplay`のcvarをtrueにしたまま処理を進めることで、bot生成完了後の`SpawnBots()`内の判定が通り実際の再生制御(`reclip_controllGame`)が自動起動する仕組みになっていた。`LoadClipAndOpen()`はプライベートマッチを開く処理だけを個別に再実装しており、このcvar経由の流れを踏んでいなかったため、`reclip_controllGame`が起動せず再生されなかった。
- **修正**: `LoadClipAndOpen()`を、`reclip_openReplay 1`を実行して既存の「Open Saved Replay」と同じcvar経由の流れに乗せるよう変更。
- 該当箇所: `ReplayClipTrainer.cpp` `LoadClipAndOpen()`

### 23. ブースト量表示のバグ修正
- **症状**: クリップ再生中（特にJumpIn前のスペクテイト中）、自分のブーストメーターに999のような3桁の異常な数値がチラつく。
- **原因**: 記録時は`GetCurrentBoostAmount()`（0〜100のパーセンテージ）で保存していたが、再生時は`SetBoostAmount()`（0.0〜1.0の割合を期待する別系統の関数）にそのまま渡していたため、桁違いの値がセットされていた。
- **修正**: 再生時も同じスケールを扱う`SetCurrentBoostAmount()`を使うように変更。記録・再生の両方で0〜100にクランプも追加。
- **追加調査（試行錯誤の記録）**: 上記修正後も「100を超える」「JumpIn時のブースト残量が不正確」という報告が続いたため、(a) 記録元を`GetReplicatedBoostAmount()`（0〜255の生ネットワーク値）に変更 → 常に0になり悪化、(b) JumpIn時に`SetCurrentBoostAmount(100.0f)`を毎ティック強制セット → 表示が200になり実際にブーストが使えなくなる、という2つの追加対応をそれぞれ試したが両方とも改善せず、いずれも撤回・原状回帰した。
- **判明した真の原因**: 上記の「100を超える/200になる/使えない」症状は、こちらのプラグインのバグではなく、**BakkesMod標準機能の「Show Boost Usage」がONになっていたことによる表示の混乱**だった。この機能をOFFにしたところ、`GetCurrentBoostAmount()`+クランプのみのシンプルな実装で正常に表示されることを確認。
- **再検証・最終結論**: 原因判明後、(b)のJumpIn時強制満タンセットも「Show Boost Usage」OFFの状態で再試験し、これも問題なく動作した。ただしユーザーの希望により、あえて満タン固定にはせず、**記録した実際のブースト残量（`GetCurrentBoostAmount()`、クランプ済み）をそのまま使う方式**を最終採用（正確さを優先）。
- 該当箇所: `ReplayClipTrainer.cpp` `SaveCar()`, `SetCar()`

### 26. 「一時停止＞先頭に戻る＞操作」でのカクつき調査（未解決）
- **症状**: クリップの先頭（Tick=0）で一時停止した状態からJumpIn操作すると、ボール・車の動きがカクつく/コマ飛びして見える。また一時停止やJumpInなしで単純に「先頭に戻る」（`reclip_skip`で大きく戻る）だけでも、ボールの残像がちらつくことがある。
- **切り分け**: クリップの途中（先頭以外）で一時停止してJumpInした場合はカクつかない → 先頭（Tick=0）特有の現象と判明。
- **仮説1（否定済み）**: 元のリプレイで先頭付近に記録されているボールタッチが原因で、ゴーストヒット救済（`ControllGamePerTick()`のsetBally=false箇所）が早期発火し、ボールが実物理に切り替わる際の速度不整合が原因ではと考え、`ballSettleTicks`（車のjumpInSettleTicksと同様の猶予期間）を実装して検証したが、**効果なし**（実装は撤回済み）。
- **仮説2（データは正常と確認）**: 車の速度がJumpIn時に0にリセットされているのではと疑い、settle終了直前とハンドオフ直後の実速度をログ計測したところ、実際には**速度は正しく維持・加速されていた**（puppetSpeed≈1263→real control speed 1260〜1283と滑らかに増加）。つまり体感の「カクつき」は内部データの異常ではなく、**描画（補間/予測）側のアーティファクトの可能性が高い**。
- **現状**: 毎ティック`SetLocation`/`SetVelocity`で強制的に座標を上書きし続ける実装が、UE3エンジン側のクライアント補間・予測描画と噛み合っていない可能性がある。BakkesMod SDKには「これはテレポートである」とエンジンに伝えて補間をリセットするような公開APIが見当たらず、確実な直し方が見つかっていない。ネイティブの一時停止/再生制御が不可能だった件（上記参照）と同様、SDKの外側にある描画ロジックの制約に起因する可能性があり、一旦保留・既知の制限として記録する。

### 41. 「自分で操作」直後の0.5秒間の自動再生、キックオフ開始クリップの停止、クリップ一覧の表示
- **「自分で操作」→一時停止解除の直後、約0.5秒だけ記録どおりに動く**: 原因は`jumpInSettleTicks`（JumpIn時に60tick）で、車の速度をエンジンに馴染ませるため「解除後も60tickは記録で車を動かしてから操作を渡す」作りだったこと。しかしJumpInは一時停止を伴うため、そのカウントは**最初の解除のあと**に消費され、解除直後の0.5秒が記録の動きになっていた（一度リセット＝再度一時停止して解除すると、カウントが0になっているので2回目から正常、という報告と一致）。一時停止中にもカウントを消費するよう変更（`ControllGamePerTick()`）。一時停止中も毎tick同じ位置・速度を設定し続けているので、解除時には既に「馴染んだ」状態になる。
- **キックオフの待ち時間から変換したクリップが再生時に動かせない**: 実機確認はできていないが、有力な原因は`ControllGamePerTick()`が毎tick`GetReplicatedRoundCountDownNumber() == 0`を条件にしていたこと（#2で、プライベートマッチ自身のカウントダウン待ちのために入れたもの）。記録にカウントダウン中のフレームがあると`SetGameInfo()`がカウントダウンのメッセージを流すため、この値が0に戻らなければ全tickが止まり、車もボールも動かなくなる可能性がある。**ネイティブのカウントダウンが一度終わったら（値が0になるのを一度見たら）以後は条件を見ない**ように変更（`nativeCountdownDone_`、`ControllGame()`でリセット）。あわせてカウントダウンの切り替わり時に`[countdown] recorded countdown N at tick T, native M`をログに出すようにした。再発する場合はこのログが手がかりになる。なお手元の保存済みクリップ30本は、記録上のカウントダウン値が全フレーム0だった。
- **クリップ一覧の表示を整理**: 「場所:」の表記を廃止し、2行目を「時間 / 人数 / フォルダ」の順に変更（年は省略し`10-23 10:36`形式。フォルダはフォルダアイコン＋名前で、「最近のクリップのみ」の表示のときだけ出す）。行が長くて見切れる場合に備え、クリップ名の全体・フォルダ・日時・人数は、行にマウスを乗せたときのツールチップでも確認できる。「読み込み」「削除」「…」ボタンは高さ32→26・文字14→12に縮小し、行の高さも56→48にした。
- 該当箇所: `ReplayClipTrainer.cpp`（`ControllGame()`, `ControllGamePerTick()`, `SetGameInfo()`）, `ReplayClipTrainer.h`, `ReplayClipTrainerGUI.cpp`（`TabClips()`）

## 未解決・既知の制限

- **日本語HUD文字化け**: 上記4の通り、根本解決には至っていない。ImGui経由のCJKフォント表示はBakkesModの制約上クラッシュするため断念。代替案（ローマ字表記、チーム+背番号表示等）は未着手。
- **F2の「Bakkesmod settings」内Pluginsタブの表示**: 実際のプラグインコードとは連動しておらず、古い/別のキャッシュ情報を表示していると思われる（詳細不明、BakkesMod側の非公開実装）。設定操作は`togglemenu ReplayClipTrainer`から行うこと。
- **ネイティブリプレイの一時停止/再生をGUIから制御することはできない**: `SetGameSpeed(0.0f)`/`SetGameSpeed(1.0f)`で試したところ、Pauseで速度が10%程度にしかならず、Playで画面が黒くなる不具合が発生したため実装を撤回。`SetPausedForScrub()`も別機能（自動再開）で試した際に実際の再生状態に反映されなかった実績があり、信頼できる制御方法は現時点で見つかっていない。詳細な追加検証は`docs/調査ログ_2026-09-23.md`参照。
- **BakkesMod標準の「Show Boost Usage」との相性**: この機能がONの状態でJumpIn中にブースト表示がおかしくなる（200等の異常値、実際に使えない）ことがある。こちらのプラグインのバグではなく標準機能側の表示混乱と判明済み。ブースト周りで違和感があれば、まずこの機能をOFFにして確認すること。
- **（解決済み・2026-10-22確認）リプレイ再生中にBakkesModの入力が効かなくなる問題**: Rocket League Season 24の新しいフリールックカメラが原因と推定され、2026-09-23時点ではプラグインのバグではなく対応不可能としていたが、その後のアップデートで改善された。詳細は`docs/調査ログ_2026-09-23.md`参照。
